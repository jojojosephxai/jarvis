# Write-back and “what changed”

Two different steps. They are not the same.

## Write-back

Say **remember that…** (also “note that…”, “don’t forget…”, “write that down…”, or “update my preferences…”).

Jarvis adds a line to a real `.md` file in the `vault` folder.

- A preference or a decision updates `Preferences.md`.
- A swim, school, goal, or about fact updates that note when it already exists.
- Something that does not fit those notes becomes one new note, then later remembers about the same thing update that note.
- The reply names the file and stops. It does not read the note back.
- It tells you to ask **what changed** if you want the receipt.

A secret (a password, a card number, a medical detail) or a large rewrite waits. Nothing is written until you press **Yes, do it**. **No, don't** leaves the vault alone.

## What changed

Say **what changed**.

Jarvis lists the file name and a short plain-English line for each recent change. That list is the receipt. A write is not claimed unless this list can name the file.

This includes:

- lines Jarvis just wrote
- lines you changed yourself in Obsidian

## Your own edits in Obsidian

Jarvis does not announce those edits on its own, and it does not read them out when the file changes.

The next time you talk, it can add one line: ask **what changed** if you want the receipt. The answer to your question still comes from the notes. The edit itself stays off that answer until you ask.

The first time Jarvis looks at the vault, the notes already there are the baseline. Only later edits show up in **what changed**.
